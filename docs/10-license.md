# License

Before you can use `fm`, someone with admin rights must accept Apple's "Apple Foundation Models CLI Legal Notice & Terms" once on the Mac.

This page is not legal advice.

## Read the terms

Print the exact current text on your Mac:

```sh
fm license --show
```

The text is short (about 90 words on 27.0.1, license id `FM1`, version `1.0`). It is not copied here because it can change with macOS updates. Always show the live output of `fm license --show`, as a GUI should too.

## What it says, in plain words

1. Read these terms before you use the Apple Foundation Models CLI.
2. If you use the CLI, you accept the normal macOS Software License Agreement (https://www.apple.com/legal/sla/).
3. You also agree **not** to access or use Apple's models from programs (programmatically) through Apple software or services, **except where Apple expressly allows it**.
4. If you do not agree, do not use the CLI.

## The unclear point: "expressly permitted"

The key phrase is "EXCEPT AS EXPRESSLY PERMITTED". The terms do not say what is expressly permitted.

Things that suggest scripting with `fm` is intended:

- Apple ships `fm serve`, and its help says any client that supports the Chat Completions API can connect to it.
- `fm serve --help` recommends `--socket` "for local Python bindings".
- WWDC26 session 334 is called "Build AI-powered scripts with the fm CLI and Python SDK".

What is **not** clear is whether a third-party app you **distribute** may drive `fm` or `fm serve` on the user's Mac.

A developer asked exactly this on the Apple Developer Forums (thread 842813, https://developer.apple.com/forums/thread/842813). The plan was: use only the public `fm serve` API, run it locally on the user's Mac, and not bypass any limits. The Apple reply did not say yes or no. It only pointed to the Apple Developer Program License Agreement and the Private Cloud Compute eligibility requirements. So, as of October 2026, there is no clear public answer.

If you plan to ship an app that uses `fm`, read those agreements and consider asking Apple directly.

## How agreement works

- Agreement is **machine-wide**. It applies to every user on the Mac.
- It must run as a privileged user: `sudo fm license`.
- It needs a terminal, because it asks a question.
- You answer `yes` or `y`. Any other answer means no, and `fm` exits.
- You are asked once, and again only if the terms change.
- Until someone agrees, every command except `fm license` shows the terms and asks (when there is a terminal), or fails.
- `fm license` is never blocked, so you can always read the terms first.

```sh
sudo fm license        # read and agree (interactive)
fm license --status    # check
fm license --show      # print the terms, no question
```

### Status messages

| Situation | Message |
|-----------|---------|
| Agreed | `Agreed to license FM1 version 1.0 on 6 Oct, 2026 at 18:04.` |
| Not agreed | `Not agreed. Run 'sudo fm license' to review and agree.` |
| `fm license` when already agreed | The terms, then `You have already agreed to these terms.` (exit 0) |
| Just agreed | `You have agreed to these terms.` |
| Answered no | `You have not agreed to these terms. Exiting.` |

### Other messages in the binary (not triggered here, because this Mac has already agreed)

| Situation | Message (shortened) |
|-----------|---------------------|
| Not admin | `Agreeing to the Apple Foundation Models CLI Legal Notice & Terms applies to every user on the machine, so it must be run as a privileged user (e.g. 'sudo fm license').` |
| No terminal | `No terminal is attached, so the agreement cannot be presented. Run 'sudo fm license' in a terminal to review and agree to it.` |
| stdin redirected | `Standard input is redirected, so there is nothing to read your answer from. Run 'sudo fm license' to review and agree to it, then re-run this command.` |
| Could not save | `Could not record your acceptance: ... Nothing was saved, so you will be asked again.` |
| Record file unreadable | Tells you to move the file aside with `sudo mv ...` and agree again. |
| Record file immutable | Tells you to run `sudo chflags nouimmutable ...`. |

### Exit code 69

When the terms are not accepted (answer is not yes, or no terminal to ask), `fm` exits with status **69** and does not run the command (from the man page and an earlier test on this Mac). 69 is `EX_UNAVAILABLE` in `sysexits.h`. Scripts and apps should treat 69 as "license not accepted" and show how to fix it.

### Where the agreement is stored

`/Library/Preferences/com.apple.fm.plist`, owned by root. Real content on this Mac:

```sh
plutil -p /Library/Preferences/com.apple.fm.plist
```

```text
{
  "FMLicenseAgreementAccepted" => {
    "date" => 2026-10-06 12:04:36 +0000
    "licenseID" => "FM1"
    "version" => "1.0"
  }
}
```

Do not edit this file by hand. Use `sudo fm license`.

## Advice for GUI apps

- Never accept the terms for the user. It is their decision, and it needs admin rights.
- Show the live text from `fm license --show`.
- Show the command `sudo fm license` with a copy button, and ask the user to run it in Terminal.
- Re-check with `fm license --status` when the user comes back.
